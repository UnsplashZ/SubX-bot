# QQ 离线时保留管理入口

用户要求：LLBot 不可用时仍能进入面板修改配置、切换官方入口。

## 修改

修改 setup.sh：删除 OneBot 登录前置门禁及扫码等待；接入服务拉取、启动失败仅警告；Bot 使用 `up -d --no-deps bili-qq-bot` 独立启动。Bot 镜像拉取及面板存活检查仍必须成功。使用 /api/live 验证面板；/api/ready 超时后再次核实存活，明确提示接入未就绪而不阻止面板部署。首次安装和已有安装升级采用同一处理；默认业务 readiness 观察 15 秒。

运行时原本已在启动 QQ 失败时保留面板并后台重试，本次无需修改 Bot 生命周期代码。原先是脚本阻止启动，不是脚本命令导致容器不停重启。官方入口切换仍要求有效配置和凭据，不能把无效官方账号视为接入成功。

## 验证

隔离 Docker 使用默认公开 Bot latest、LLBot latest 和虚构测试账号，不登录真实 QQ：已有配置升级运行退出码 0；容器 healthy，RestartCount=0；/api/live 为 200，/api/ready 为 503。实际登录面板 200，读取配置 200，使用 generation 提交配置更改 200，证明离线时管理入口和配置保存可用。

部署状态机 20 项、QQ 启动恢复 12 项通过，包括两种 Provider 启动失败保留面板、重试恢复、配置事务取消旧重试及切换释放启动隔离。LLBot 容器启动失败另有部署测试，仍会启动 Bot。

未使用真实官方凭据登录官方 QQ，本次官方入口切换依赖已有生命周期模拟测试；未修改远端正式部署。旧隔离验收报告中“登录失败阻止 Bot 启动”的行为已被本修改替代。

补充：修改后脚本从全新空目录选择默认 LLBot（未登录）执行完成，退出码 0；同样 live=200、ready=503、面板登录/配置读取=200、healthy、RestartCount=0。首次安装及升级隔离容器和网络均已清理。
